## 2026-10-21：0.2.2-dev 固定开发签名

用户反馈升级因签名不同失败，要求使用同一签名。原先 GitHub 托管 runner 每次生成的调试密钥未保留，无法从旧 APK 恢复私钥。现在生成项目专用 PKCS12 私钥，保存在仓库外私有目录，并把公开证书指纹固定到 `android/development-signing.sha256`；不使用公开测试密钥，不向 Git、公共 artifact 或 Release 上传私钥。

Gradle 缺少签名配置时只生成 unsigned 中间包，禁止再次自动换用随机调试密钥。CI 支持从唯一 Repository Secret `ROCKS_ANDROID_SIGNING` 还原原密钥、校验指纹，并在第二个全新 runner 上再次构建核对证书；PR 不读取 Secret。详细配置、备份和迁移见 `docs/Android签名.md`。

当前 CLI 可连接仓库，但 Actions Secrets API 返回 **403 Resource not accessible by integration**，不能自动保存 Secret，也没有扩大账号权限。私有配置已准备好，需所有者手动保存。配置缺失时两次 CI 构建均仅提供 unsigned 中间包，后续可在持有固定私钥的受控工作区签名、校验证书并发布；不能声称 CI 已配置成功。

本机已验证真实 PKCS12 的证书与公开指纹一致，正确配置可读取，错误指纹、非法 base64、别名/密码换行与未知格式均拒绝；没有输出密码或私钥。版本提升为 `0.2.2-dev` / versionCode 4。
