# 双内核刷新率选择对照 1.1

两份 1.1 测试包都增加了同一刷新率选择器，可以覆盖安装此前的 1.0 对照包。默认跟随系统；可选当前分辨率下系统报告的实际档位，以及“最高（具体 Hz）”。每份应用分别记住选择，进入后台撤回窗口申请，回到前台或冷启动后恢复；“最高”随显示能力变化重新计算。固定档位失效时提示并退回跟随系统。

## 建议怎么测

1. 在手机上覆盖安装 Chromium 和 Firefox 1.1，两份应用都选“最高”，或都选同一个具体档位。
2. 等待几秒，点击页面“重新计数”，分别记录顶部“申请 Hz”“系统报告 Hz”，以及网页 rAF FPS / P95。
3. 对比手动慢拖、快速滑动及惯性滚动，再比较自动滚动。选项切换本身不刷新网页，两个包仍使用同一离线页面和动画。
4. 若手机系统另有按应用控制高刷的设置，请让两个测试应用采用相同设置。申请值和系统报告值不同不能直接认定失败，更不能据申请值声称网页已达到对应 FPS。

程序只通过 WindowManager.LayoutParams.preferredRefreshRate 提交窗口偏好，preferredDisplayModeId 保持为零，不固定屏幕模式、不指定分辨率、不写系统全局设置，也不修改浏览器内核的帧率偏好。选项来自当前物理分辨率的 supportedModes；Android 12+ 合并无缝备选刷新率。不会凭空增加手机不支持的 60/120Hz，也不会将仅在其他分辨率可用的高刷列入。

参考：[Android 窗口刷新率偏好](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#preferredRefreshRate)、[显示模式与无缝备选频率](https://developer.android.com/reference/android/view/Display.Mode#getAlternativeRefreshRates())。系统仍可忽略或调整申请；网页 rAF 是回调频率估算，不能代替真实合成帧数和触摸体验。

## 怎么比较

1. 两个应用采用相同的系统刷新率与省电设置；系统若有按应用设置高刷的选项，请将两份测试应用设为相同。
2. 先打开默认“本地测试”页，等待约 5 秒，记录顶部“系统报告 Hz”和页面“rAF FPS / P95”。
3. 分别慢拖、快滑并观察松手后的惯性滚动，再测试“自动滚动”。暂停后可按“重新计数”重新采样。
4. 使用地址栏在两份应用打开同一 HTTP(S) 网站，比较实际滚动感受。两者均不主动申请固定 60/120Hz，不更改引擎帧率偏好或用户代理。

“系统报告”来自本应用 Display.getRefreshRate；rAF FPS 是网页回调频率的估算，P95 是本次采样中 95% 帧间隔的上界，不是实际合成呈现帧数或触摸延迟。60Hz 对应的理想间隔约 16.7ms，120Hz 约 8.3ms。系统 Hz 不同的结果需先考虑系统按应用分配的策略；系统 Hz 相同而计数或滚动表现不同，才进一步检查引擎与呈现过程。高刷手机上的结果尚待用户实测。
