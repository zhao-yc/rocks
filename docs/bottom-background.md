# 网页底栏背景衔接

Android Gecko 主线在存在可见的贴边固定栏时，将它的纯色延伸到地址胶囊背后及底部安全区；其余情况保持透明。地址胶囊的外观、按钮和滚动交互不变，网页物理尺寸不随背景层变化。

## 检测边界

- 独立内置隔离扩展只在顶层 HTTP/HTTPS 页面运行；它不依赖扩展管理器中的用户扩展，也不出现在用户扩展列表中。
- 候选必须为 `fixed` 或设置了 `bottom` 的 `sticky` 元素，覆盖至少 80% 可视宽度，通过多个命中点的遮挡检查，且底边距 Gecko 实际可用底边不超过 4 CSS 像素。
- Gecko 仅在合成阶段抬高 `fixed`；`sticky` 使用其实际 DOM 位置。位于地址胶囊下面的吸附栏不能冒充可用底边的栏，否则纯色层会盖住它；这种情况保留透明，不修改网站 CSS。
- 纯色及半透明纯色可沿祖先合成；背景图片、渐变、滤镜、整体透明度和无法解析的颜色空间保守回退为透明。小悬浮按钮不触发整条背景。
- 检测按加载、滚动、窗口/可视视口变化、DOM/样式变化及焦点事件合并，最多每秒十次；相同结果不重发，空闲时没有持续轮询。不会分析子框架内部、封闭 Shadow DOM，或保证识别没有产生相关事件的任意 CSS 动画。
- 是否为当前标签由浏览器已有的标签激活事件在扩展内部同步，不依赖 Gecko 启动时尚未就绪的 `document.hasFocus()`。后台标签停止候选扫描，原生端仍独立校验当前会话与文档。

## 受限通道

所有者已明确授权本功能的专用通信例外。内置扩展 `bottom-background@rocks.internal` 只上报文档标识、视口、候选矩形与 RGB 色值。原生端校验扩展身份、顶层来源、会话、文档及消息边界，不接收网页原生命令。报告仅存于内存，不读取正文/表单，不写入浏览数据，不上传结果。

导航、刷新、标签切换、前后台和崩溃使旧端口失效；键盘期间清除报告并停止显示背景；全屏时隐藏背景，恢复后重新检测。扩展失败时保持透明，正常浏览不受影响。底栏背景衔接是对苹果效果的近似实现，不是 Safari 内部算法的复刻。

原生端只在文档位置提交后接受连接，避免旧页面在导航等待期重新上报。扩展针对启动和提交时序只作四次有界重试，后台或离开文档立即取消，不形成持续轮询。Gecko 在合成阶段移动固定底栏而不改变 DOM 矩形，因此原生端在同一表面坐标系内补偿固定元素偏移后再比较底边；纯色层也阻止触摸穿透到已覆盖的网页内容。

## 验证

脚本回归并入 `node --test scripts/test-gecko-extension.mjs`；原生解析、贴边阈值和文档失效策略并入 `testDebugUnitTest`。完整检查使用 `gradle -p android/gecko-demo :core:test testDebugUnitTest lintDebug assembleDebug`。

视觉验收须分别记录模拟器和真机证据：百度固定评论栏、白/深色固定栏及无固定栏页面、动态显隐、吸附状态、Dark Reader、收放动画、键盘、横屏、手势/三键导航、全屏恢复。JVM 与脚本测试不证明设备渲染正确。
